# 사용자 경험 고려

작성일: 2026-08-27  
대상: D3BUG 업무 매칭 서비스

## 실행 상태 점검

- [x] 입력값 검증, 인증, 인가, 민감 정보 처리를 적용했다.
- [x] 파일 업로드와 채팅 조회에 제한을 두어 자원 사용을 관리했다.
- [x] 중도포기, 파일 용량 초과, 긴 텍스트 등 예외 상황에 사용자 안내를 제공한다.

## 1. 보안과 입력 검증

| 확인 항목 | 적용 내용 | 기대 효과 |
| --- | --- | --- |
| 로그인과 권한 | 업무·채팅·프로필은 로그인한 사용자만 이용할 수 있으며, 관리자 기능은 관리자 계정만 접근할 수 있다. | 다른 사용자의 업무나 채팅 정보에 접근하는 일을 방지한다. |
| 채팅 참여자 확인 | 채팅방의 의뢰자와 수행자만 메시지와 첨부 파일을 보낼 수 있다. | 제3자가 대화에 개입하거나 파일을 올리는 일을 막는다. |
| 비밀번호 보호 | 비밀번호는 암호화하여 저장하고, 회원 탈퇴 시에도 비밀번호를 다시 확인한다. | 계정 정보가 그대로 노출되는 위험을 줄인다. |
| 중요 정보 분리 | DB 비밀번호와 AI API 키는 소스 코드가 아닌 개인 환경 설정으로 관리한다. | 저장소 공유·배포 과정에서 민감 정보가 노출되는 일을 줄인다. |
| 파일 검증 | 파일 크기와 허용 형식을 확인한 뒤 업로드한다. | 지원하지 않는 파일이나 과도하게 큰 파일의 업로드를 막는다. |

## 2. 응답과 자원 사용 고려

| 고려한 부분 | 적용 내용 | 사용자 경험 |
| --- | --- | --- |
| 첨부 파일 크기 | 첨부 파일은 최대 6MB까지만 업로드할 수 있다. | 큰 파일 때문에 전송이 오래 걸리거나 화면이 멈추는 상황을 줄인다. |
| 채팅 메시지 조회 | 채팅방에서는 최근 메시지 100개만 불러온다. | 대화가 길어져도 채팅방에 비교적 빠르게 들어갈 수 있다. |
| DB 연결 대기 | DB 연결 수와 연결 대기 시간을 제한한다. | 외부 DB가 느릴 때 서비스가 오래 멈추는 상황을 완화한다. |
| AI 추천 실패 | AI 설명 생성에 실패해도 기본 점수 기반 추천 결과는 유지한다. | 외부 AI 오류 때문에 지원자 추천 화면 전체가 실패하지 않는다. |

## 3. 예외 상황과 사용자 안내

| 사용자 상황 | 적용한 처리 | 사용자에게 보이는 결과 |
| --- | --- | --- |
| 의뢰자가 업무를 중도포기함 | 채팅방을 바로 삭제하지 않고 취소 상태로 보존한다. 이후 메시지·첨부 전송은 막는다. | 채팅방에서 **“의뢰자가 글을 삭제했습니다.”**라는 안내를 확인할 수 있다. |
| 중도포기한 업무 화면을 새로고침함 | 오류 페이지 대신 내 프로필 화면으로 이동시킨다. | **“의뢰자가 글을 삭제했습니다. 내 업무 목록으로 이동했습니다.”**라는 안내를 볼 수 있다. |
| 6MB를 넘는 결과 파일을 선택함 | 파일 선택 단계에서 용량을 확인하고 전송을 막는다. | **“첨부 파일 용량이 너무 커서 전송할 수 없습니다. 6MB 이하 파일을 선택해주세요.”**라는 안내를 볼 수 있다. |
| 파일명·업무 내용·후기가 너무 김 | 기본 화면은 말줄임표로 폭을 유지하고, 필요한 경우 더보기로 전체 내용을 펼친다. | 긴 글 때문에 화면이 옆으로 밀리거나 잘리지 않는다. |
| AI 기능 설정이 없음 | AI 기능만 비활성화하고 서비스는 실행되도록 처리한다. | API 키 설정 문제로 서비스 전체가 실행되지 않는 상황을 막는다. |

## 정리

D3BUG는 사용자가 오류 화면만 보고 멈추지 않도록, 문제가 발생한 이유와 다음 행동을 화면에서 안내하도록 구성했다. 또한 파일 용량, 채팅 조회 범위, DB 연결 대기 시간을 제한해 기본적인 자원 사용도 함께 고려했다.

## 4. 대표 사례 정리 — 중도포기 업무의 오류 화면 개선

### S · Situation

의뢰자가 매칭 또는 진행 중인 업무를 중도포기하면 해당 업무가 삭제됐다. 이미 채팅 중이던 수행자가 채팅방에서 메시지를 보내거나 진행 화면을 새로고침하면 Whitelabel Error Page가 나타났다. 수행자는 왜 화면을 볼 수 없는지, 업무가 취소됐는지 바로 알기 어려웠다.

### T · Task

업무가 중도포기된 뒤에도 수행자가 취소 사실을 바로 알 수 있게 하고, 더 이상 진행할 수 없는 업무에서 메시지나 파일을 보내지 못하도록 해야 했다. 동시에 기존 채팅 기록은 이력 확인을 위해 남겨 둘 필요가 있었다.

### A · Action

- 중도포기 시 채팅방을 즉시 삭제하지 않고 `task_deleted` 상태로 보존했다.
- 채팅방에 **“의뢰자가 글을 삭제했습니다.”** 안내를 표시하고 메시지 입력창을 숨겼다.
- 화면을 우회해 전송을 시도해도 서버에서 메시지·첨부 파일 전송을 막도록 처리했다.
- 삭제된 업무의 진행 화면에 다시 접속하면 오류 페이지 대신 내 프로필로 이동시키고 안내 문구를 표시했다.

### R · Result

- 수행자는 기술적인 오류 화면 대신 업무가 삭제된 이유를 즉시 확인할 수 있다.
- 취소된 업무에 메시지나 첨부 파일이 추가되는 것을 방지했다.
- 기존 채팅 기록은 남아 있어 이후 문의나 이력 확인에 활용할 수 있다.
