# BaroHae · 바로해

*24시간 이내 처리가 필요한 원격 디지털 업무를 의뢰인과 작업자에게 연결하는 긴급 업무 매칭 플랫폼*

## 1. 서비스 소개

개발 오류 수정, 발표 자료 보완, 문서 검토, 번역처럼 짧은 시간 안에 해결해야 하는 디지털
업무는 일반 외주 플랫폼의 긴 견적·계약 절차와 잘 맞지 않습니다. 의뢰인은 마감 전에 작업
가능한 사람을 빠르게 찾아야 하고, 작업자는 지금 수행할 수 있는 업무와 보상을 명확히 확인할
수 있어야 합니다.

바로해는 *업무 등록 → 지원자 비교 → 작업자 선택 → 실시간 채팅 → 결과 제출 → 승인 → 정산*
까지를 하나의 흐름으로 연결합니다. 실제 금액 대신 시간 기반 재화인 *품*(1품 = 30분)을
사용해, 예약·조정·반환·정산 전 과정의 데이터 정합성을 구현하는 것을 핵심 과제로 삼았습니다.

초기 범위는 발표 자료, 개발, 문서 검토, 번역처럼 원격으로 처리 가능한 24시간 이내 단기
업무로 제한했습니다.

## 3. 주요 기능

### 인증 · 회원

- 이메일 회원가입·로그인, 비밀번호는 BCrypt(strength 12) 해시로 저장
- *카카오 · 구글 OAuth2 소셜 로그인*, 소셜 계정 연동 정보를 별도 테이블로 관리
- 15분 내 로그인 5회 실패 시 일시 제한, 정지 계정 차단과 기존 세션 만료
- 프로필 수정(닉네임·소개·기술 태그·포트폴리오 URL·프로필 이미지)과 회원 탈퇴
- 신규 가입 시 4품 지급 (멱등성 키로 중복 지급 차단)

### 업무 등록 · 탐색

- 9개 카테고리 — 발표 자료, 개발, 문서 검토, 번역, 인터뷰, 포트폴리오, 디자인, 데이터, 기타
- 마감은 한국 시간 기준 등록 시점부터 24시간 이내, 요청 품은 30분 단위이며 보유 잔액 이내
- 제목·기술 검색, 카테고리 필터, 마감순·최신순·높은 품순 정렬, 페이지네이션
- 참고 링크와 첨부 파일(최대 6MB)을 별도 필드로 분리 관리
- *AI 업무 등록 보조* — 자연어 상황 설명을 제목·카테고리·기술·완료 기준·상세 설명으로 구조화

### 매칭 · 업무 진행

- 업무 지원과 지원 취소, 동일 업무 중복 지원 차단
- 지원자별 프로필·기술·평점·예상 소요 시간을 한 화면에서 비교
- *AI 작업자 추천* — 서버가 기술 유사도, 카테고리 완료 경험, 기한 준수율, 채팅 평균 응답
  속도, 현재 작업량으로 순위를 계산하고 AI가 추천 사유와 주의점을 보강합니다. AI 호출이
  실패하거나 비활성화된 경우에도 서버의 데이터 기반 추천 결과를 그대로 제공합니다.
- 상태 전이: 모집 → 매칭 → 진행 → 제출 → 완료 / 취소 / 분쟁
- 결과 제출, 수정 요청, 완료 승인, 리뷰 작성, 분쟁 접수
- 마감 초과 제출에 대한 지연 지표 기록과 지원 제한, 관리자의 페널티 면제·복원

### 실시간 채팅

- 의뢰인이 작업자를 선택하면 업무별 1:1 채팅방 자동 생성
- *STOMP WebSocket 기반 실시간 메시지 수신*
- 상대방이 실제로 채팅방을 열었을 때 갱신되는 읽음 처리
- 이미지 미리보기, 비공개 첨부 파일 다운로드, 채팅방 나가기와 퇴장 시스템 알림

### 품(시간 재화) 원장

- 1품은 내부적으로 30분으로 저장하고, 사용 가능 잔액과 업무 예약 잔액을 분리 관리
- 등록 시 예약, 수정 시 차액 조정, 취소·삭제·만료 시 반환, 완료 승인 시 작업자 정산
- 모든 이동을 증감량·처리 후 잔액·사유·관련 업무·멱등성 키와 함께 거래 원장에 기록
- 행 잠금과 트랜잭션으로 동시 잔액 변경의 정합성을 보호하고 중복 정산을 차단

### 알림

- 지연 기록·지연 경고·지원 제한·페널티 면제·페널티 복원·지원자 선택 결과 알림
- 프로필 내 알림 센터에서 개별 확인과 전체 읽음 처리

### 관리자

- 회원·업무·분쟁·채팅·품 거래 원장·감사 로그 관리 (검색, 날짜 필터, 페이지네이션)
- 회원 정지·활성화, 사유를 남기는 품 지급·차감, 모집 중 업무 취소와 예약 품 반환
- 분쟁 검토 시작·해결·기각, 채팅방 조회와 메시지 블라인드·복원
- 모든 관리자 조치를 관리자·작업·대상·상세·시각과 함께 감사 로그에 보존

## 4. 설계 포인트

| 주제 | 구현 |
| --- | --- |
| 재화 정합성 | 멱등성 키 + 행 잠금 + 트랜잭션으로 중복 차감·중복 정산 차단, 모든 이동을 원장에 기록 |
| 파일 보안 | 공개 URL을 저장하지 않고, 참여자 권한 검사 후 5분간 유효한 서명 URL을 발급 |

| 시간대 | DB는 시간대 정보를 보존하고 커넥션 초기화 시 세션 타임존을 `Asia/Seoul`로 고정, 화면은 KST 표시 |
| 스키마 관리 | Flyway로 V1~V21 버전 관리, 애플리케이션 시작 시 검증하며 적용된 마이그레이션은 수정하지 않음 |
| 실행 분리 | web / db / ai-google 프로필로 화면·DB·AI 연동을 독립적으로 켜고 끌 수 있도록 구성 |

## 5. 실행 방법

`.env.sample`을 참고해 환경변수를 설정하고 Java 17로 실행합니다.

### 프로필

| 프로필 | 용도 |
| --- | --- |
| web | DB·보안·AI 연동 없이 화면만 확인 |
| web,db | Supabase 연결, 로그인·업무·채팅 등 전체 기능 (AI 제외) |
| web,db,ai-google | Gemini 연동까지 포함한 전체 기능 |

### 실행


powershell
.\gradlew.bat bootRun

### 테스트

Supabase 연결 없이 실행하는 일반 테스트입니다.


powershell
.\gradlew.bat test

Supabase 통합 테스트는 supabase 태그로 분리되어 있으며, 테스트 데이터를 롤백합니다.


powershell
.\gradlew.bat supabaseTest

### Supabase Storage 설정

- 버킷 이름: SUPABASE_STORAGE_BUCKET 값과 동일하게 설정
- 공개 버킷: 비활성화
- 최대 파일 크기: 6MB 이상
- 허용 MIME 유형: `image/, text/, application/pdf, application/zip,
  application/x-zip-compressed,
  application/vnd.openxmlformats-officedocument.wordprocessingml.document,
  application/vnd.openxmlformats-officedocument.presentationml.presentation,
  application/vnd.openxmlformats-officedocument.spreadsheetml.sheet,
  application/x-hwp, application/haansofthwp`
- `SUPABASE_SERVICE_ROLE_KEY`는 서버 환경변수로만 관리하며 브라우저와 Git 저장소에 노출하지 않습니다.

### 데이터베이스 마이그레이션

db 프로필로 실행하면 Flyway가 V1~V21 이력을 검증하고 아직 적용되지 않은 마이그레이션만
순서대로 적용합니다. 채팅 스키마 정렬, 품 원장 보존, 채팅방 나가기, 관리자 감사 로그,
메시지 블라인드, 참고 링크·첨부 파일 분리, OAuth 계정, 제출 지연 평가와 페널티 면제,
회원 알림과 지원자 선택 알림이 포함됩니다. 이미 운영 DB에 적용된 마이그레이션 파일은
수정하지 않습니다.

## 9. 개발 협업 규칙

기능이나 수정 단위로 브랜치를 생성합니다.

### PR 작성 기준

- 작업 목적
- 주요 변경 파일
- 변경된 기능
- DB 변경 여부
- 환경변수 추가 여부
- 화면 변경 시 캡처
- 리뷰어가 확인해야 할 위험 요소

### 리뷰 기준

- 기능 요구사항 충족 여부
- 일반 회원과 관리자 권한 분리
- 다른 회원 데이터 접근 가능성
- 재화 중복 차감 및 반환 가능성
- 업무 상태 전이의 적절성
- 예외 발생 시 롤백 여부
- 개인정보 및 서비스 키 노출 여부
- DB 마이그레이션의 기존 데이터 영향 파악 (고정값 사용 금지)
- 불필요한 코드나 중복 로직

### 공통 파일 수정

SecurityConfig, 공통 헤더와 레이아웃, application.yaml, 전역 CSS, 공통 예외 처리,
DB 마이그레이션, 주요 도메인 엔티티를 수정할 때는 관련 담당자에게 사전 공유하고 변경
범위를 최소화합니다.
